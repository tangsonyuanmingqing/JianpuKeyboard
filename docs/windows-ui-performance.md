# Windows 真实界面性能验证

本验证针对 v1.6.0 的 100×100 智能表格交互预算：当前开发机预热后，各类常用操作的 P95 小于 100ms。

当前结论：2026-09-26 最终版本的四场景各三轮真实窗口实测全部通过，共 3,000 个正式样本。默认／大面板、有效／9,999 错误数据均覆盖；详见[最终四场景验收](#最终四场景验收)。只适用于当前开发机、窗口和 DPI，不外推其他设备或真实输入法端到端延迟。

原始证据随 [v1.6.0 Release](https://github.com/tangsonyuanmingqing/JianpuKeyboard/releases/tag/v1.6.0) 提供为 `JianpuKeyboard-v1.6.0-windows-performance-reports.zip`。本文中的 `build/performance/` 链接是本地复查入口；在 GitHub 阅读时，下载证据包并解压到项目的 `build/performance/` 即可核对。包内保留正式结果及正文引用的失败探测／诊断，不将它们混入最终验收。

## 测量范围

运行实际 Windows Runner 与 `JianpuKeyboardApp` 主页，使用 Profile 编译模式、项目字体和真实 Provider 链路。填满 100 行、100 列，谱行和词行交替；曲谱、草稿和快照使用临时目录中的真实 Repository 与原子文件存储，不覆盖日常数据。保留正常的自动保存延迟和后台写入。

| 操作 | 触发和结果校验 |
| --- | --- |
| 输入 | 已聚焦谱格中的数字在 `3`、`4` 间交替，校验文档和文本控制器内容 |
| 选择 | 点击相邻谱格，校验选中行列；避免连续点击同一谱格触发音符选择器 |
| 纵向滚动 | 注入鼠标滚轮事件，以 180 逻辑像素步长往返，覆盖表格底部；校验正文和冻结列同步 |
| 横向滚动 | 注入水平滚轮事件，以 180 逻辑像素步长往返，覆盖表格最右侧；校验滚动位置 |
| 撤销 | 在已编辑谱格中写入 `5`，通过 Ctrl+Z 恢复 `4`，校验文档与可见文本 |

每项每轮预热 10 次、正式测量 50 次，默认运行三个独立应用进程。每类操作累计 150 个样本，共 750 个正式响应延迟样本。

## 时间口径

计时从测试框架调用操作前开始，到操作之后的结果帧光栅化结束为止。输入采用标准 `tester.enterText`，因此结果包含框架定位目标文本控件及同步消息的开销；其他操作使用已缓存的点击坐标、滚轮事件或显式物理按键。测试记录结果帧的 `frameNumber`，与引擎报告的同编号 `FrameTiming.rasterFinishWallTime` 匹配，并保存两个原始墙钟时间戳。引擎可能批量延迟回传帧数据，回传等待不计入响应时间。

测量阶段使用 `benchmarkLive` 帧策略，避免 `tester.pump()` 人工生成计时帧。结果帧同时记录 UI 构建时间和光栅化时间。每次操作必须通过行为断言，缺失匹配帧、目标没有改变或出现异常会使验证失败。

P95 使用最近秩方法：排序后取第 `ceil(n × 0.95)` 个值。每轮每类操作及合并样本都必须满足 P95＜100ms，不以多个类别平均值替代单项验收。最大延迟另行保留，P95 达标不表示不存在个别慢帧。

这覆盖实际界面的事件处理、状态更新、布局、绘制和引擎光栅化，未包含操作系统物理输入设备延迟、中文输入法组词提交或显示器扫描显示时间。输入项目使用已聚焦谱格的数字编辑，不能据此宣称所有中文输入场景均已测量。Profile 模式和框架输入注入也不等同于人工操作安装包。

测量方法依据 [Flutter 官方性能集成测试说明](https://docs.flutter.dev/cookbook/testing/integration/profiling)，具体逐帧时间匹配使用当前本地 Flutter SDK 的 `FrameTiming` 接口。

### 实施与回归

先建立失败回归，再逐步修改并使用同一原生窗口测量回路验证。主要修改集中在表格渲染和输入控件，不改变表格数据格式或存储协议：

- 未变化的单元格子树按内容、选择、比例、主题和问题提示复用；缓存有上限。
- 只创建水平视口附近的列，使用占位宽度保留完整滚动范围；活动格保留，跨视口定位自动滚动并聚焦。
- 离屏非活动编辑器在帧结束、元素卸载后释放控制器和焦点节点，回到视口时从文档恢复内容。
- `SmartGridTextField` 使用 Flutter `EditableText` 与平台感知的 `TextSelectionGestureDetectorBuilder`，去掉单元格不需要的 Material 表单／装饰／计数器布局，保留整格点击、字体、居中、文本输入和快捷键。
- 横向滚动复用表头和冻结列子树；正文不再创建被冻结列遮挡的重复行头控件。
- 控制器只同步实际变化的数据，避免视口保存覆盖未提交的中文组词；编辑监听按稳定行 ID 找到重排后的目标。
- 自动移焦前记录原文档，多格歌词写入只生成一次历史记录；快速交替点击始终更新选择。

新增 9 项回归覆盖控件复用、可见列数量、快速交替点击、跨视口聚焦、中文组词、行重排、离屏释放、问题／比例刷新及多格歌词撤销／重做。完整 `flutter test`：**387 项通过**；`flutter analyze`：无问题。

### 单因素探测与取舍

1. 先增加真实格子渲染调用路径的读取计数回归。旧实现的小视口渲染读取 10,000 项问题列表 44,396 次；改成每次 Widget 更新建立坐标索引、滚动直接查找后回归通过。保留首条问题的优先顺序及问题／比例变化时的缓存刷新。
2. 仅改索引的单轮横滚仍为 115.187ms，**不足以解决超预算**。不将这一小幅变化当成主要收益，记录为[索引探测](../build/performance/smart_grid_ui_performance_20260926-150922-large-errors-summary.json)。
3. 默认纵向预建缓存让 250 高度面板挂载 11 行编辑器，超过视口最多 7 行。增加计入离屏元素的失败回归，再将编辑器正文／冻结列的滚动缓存设为 0；只保留视口行和框架必需的活动元素。单轮横滚降为 89.863ms、纵滚 77.314ms，五项通过：[预建范围探测](../build/performance/smart_grid_ui_performance_20260926-151327-large-errors-summary.json)。

以上单轮报告用于选择改动，不替代最终三轮验收。没有增加物理横向滚动尾部空白、没有调整生产默认配置。这里的“余量”是响应预算余量。完整转换仍只在用户点击转换时执行；当前编辑／选择预算未显示必须引入增量校验缓存，因此保持无状态全表语法检查，避免新增失效规则。

后续完整复验发现：仅索引＋限制离屏预建仍不足以稳定通过密集错误大面板。三轮合并横滚 P95 为 95.230ms，但第 1 轮为 102.107ms，因此仍判失败，见[中间版本复验](../build/performance/smart_grid_ui_performance_20260926-152517-large-errors-summary.json)。显式固定列表行高的三轮合并为 96.857ms，第 1／3 轮分别 100.508／103.373ms，见[固定行高探测](../build/performance/smart_grid_ui_performance_20260926-152850-large-errors-summary.json)；这项没有证实收益的生产改动已撤掉。上述报告不纳入最终验收，也未靠重复抽样或放宽阈值掩盖失败。

最终候选增加行级非交互错误／警告图标绘制：沿用 `MaterialIcons` 字体及原位置、颜色与尺寸，每行最多布局两种图标字形，避免每格独立的 `Icon` 布局树。边框、提示、编辑器与语义仍由格子负责，行绘制不接管点击。字体构造继续集中在 `AppTypography`。已加载真实图标字体，对原 `Container → Stack → Icon` 布局和行绘制逐像素比较：三种比例、LTR／RTL 字形方向、DPR 1.5 均一致。另有问题出现／消失时保持编辑器身份和焦点、缩放后末行可达、实际拖动配对行的回归。

### 按职责整理

- `smart_grid_validation.dart` 集中格子语法检查、全表问题坐标及问题模型；编解码、转换与页面使用同一规则，原入口保留兼容导出。不把转换和歌词对齐混入编辑时校验。
- `TableScrollLink` 封装正文／冻结列双向同步、范围裁剪、防回入和监听解除；编辑表格与输出表格复用，控制器仍由各页面持有。
- `persistence_state_notifiers.dart` 仅共享存储健康与写入状态转换；各域保留自己的 Provider、初始状态、错误信息和 Repository，不合并草稿与曲谱库事务。
- 面板布局持久化通过 Provider 注入，使实际存储和隔离测试配置可切换，页面不自行构造依赖。

未按文件行数拆分页面，也未将导出、曲谱库操作等流程机械搬到一组转发文件。全量回归 **399 项通过**，静态分析无问题；最终原生矩阵结果见后续记录。
