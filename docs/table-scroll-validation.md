# 表格滚动条重构验证（2026-09-27，未发布）

本轮仅重构输入表格、转换输出表格和曲谱库表格预览的滚动轨道，不改数据格式、版本号、百分比缩放控制、校验缓存或输出渲染策略；不提交、推送或发布。历史性能结果保留在 [Windows 性能验证](windows-ui-performance.md)。

## 原故障与单变量验证

用户复现路径是输入页选中格子后，底部滑块消失，鼠标移回底边也无法操作。新增 Windows 目标回归先检查选格前真实绘制且可命中的滑块，再选格、移回底边、检查绘制和实际拖动偏移；旧实现选格前通过，选格后失败。这与新增的“有溢出常显”规则分开验证，不用 `thumbVisibility` 代替可操作性。

单变量探测只将旧输入横向滚动条的方向筛选改成目标 `ScrollPosition` 筛选：选格后的绘制和真实拖动恢复，焦点保留断言仍失败。因此已确认的消失原因是格内横滚／尺寸通知污染整表滑块绘制信息；原截图不足以单独证明遮挡、热区或计时器故障，不将这些静态风险记为已确认根因。

Windows 桌面自动滚动条可能给正文和冻结列分别增加一条，旧表还有显式滚动条。新测试在 Windows 目标下断言每张表只有两条显式 `RawScrollbar`，没有表内自动 `Scrollbar`，同时曲谱库页面外层滚动条仍存在。

## 实现边界

`TableScrollFrame` 负责固定 24 像素轨道、主题样式、目标位置筛选和表内点击区域。正文与轨道分开布局，避免覆盖格子以及重复扣除 viewport padding；纵向轨道从表头下方开始，右下角独立留给调整把手。滚动和尺寸通知只向对应轨道转发，转发通知不冒泡污染页面。

控制器、正文／冻结列同步、可见列、活动编辑器和视图恢复仍留在原模块。滑块绘制、命中、拖动、轨道翻页和拖动取消均使用 Flutter 原生 `RawScrollbar`，未添加自写拖动算法。旧悬停模块及其显隐测试移除，用行为回归替换。

## 回归覆盖

- 共享轨道：无溢出、仅横向、仅纵向、双轴；无溢出仍保留占位；内容扩缩后的真实尺寸通知；嵌套长文本横滚及尺寸通知隔离；转发通知不重复传给页面。
- 输入、输出、曲谱库预览分别实际拖动两轴、点击轨道、到达两端、拖出面板释放、移动进入拖动后取消、取消后鼠标移动不继续拖动、再次拖动。
- 输入页选格后滑块绘制／命中和偏移；输入谱选择弹窗返回、输出父级比例重建、曲谱库键位弹窗返回后实际可操作。
- 输入／输出／曲谱库纵向拖动后的正文／冻结列同步，曲谱库页面位置不随表格轨道改变，页面自动滚动条保留。
- 输入比例调整、右下角把手拖动与轨道互不抢操作、增删行列后的双轴／无溢出切换。
- 活动歌词格跨两轴滚动后选择、焦点、编辑器身份、完整 `TextEditingValue`（含光标和 composing range）保持；提交并继续输入后多格落值正确，Ctrl+Z 一步撤销。

主要用例：[共享轨道](../test/features/converter/table_scroll_frame_test.dart)、[输入／输出真实滑块](../test/features/converter/table_scroll_interaction_test.dart)、[曲谱库预览](../test/features/library/song_library_scroll_test.dart)、[原编辑回归](../test/features/converter/smart_grid_editor_test.dart)。测试通过公共 `ScrollbarPainter` 命中测试寻找实际绘制的滑块，并注入鼠标手势，再断言控制器偏移、数据和焦点；不访问私有拖动状态。

## 原生窗口复跑

原生入口复用输入／输出／曲谱库行为用例，使用实际 Windows 平台与实际窗口尺寸，不启用 debug 平台覆盖。正常保存并关闭日常应用后运行：

```powershell
flutter drive --profile -d windows `
  --driver=test_driver/table_scroll_driver.dart `
  --target=integration_test/table_scroll_test.dart `
  --dart-define=INTEGRATION_TEST_SHOULD_REPORT_RESULTS_TO_NATIVE=false
```

独立记录保存到 `build/performance/table_scroll_native_<时间戳>.json`。这是框架鼠标和输入法编辑值注入，不是物理鼠标或 Windows 中文输入法端到端测量。

## 本轮验收结果

- 完整 `flutter test --no-pub`：408 项通过；`flutter analyze --no-pub`：无问题。
- Windows Profile 原生交互：5 个行为用例全部通过；实际物理客户端 1898×1024、DPR 1.5。[最终原生记录](../build/performance/table_scroll_native_1790492427879.json) 保留每个用例的结果。
- 原生入口早期探测因 Profile 不允许 debug 平台覆盖、模拟快捷键未提供物理键码而失败，分别保留 [平台覆盖探测](../build/performance/table_scroll_native_1790491922603.json) 与[键码探测](../build/performance/table_scroll_native_1790492171829.json)，不作为验收；后续修正均局限于测试配置，未改生产行为。14:57 的中间通过记录也不替代最终同设备取消测试。
- 四场景各三轮原生性能矩阵全部通过，共 3,000 个正式样本。最慢单轮 P95 为 86.106ms，最慢合并 P95 为 83.084ms；大面板密集错误纵滚有一个 103.324ms 最大响应，保留慢帧事实，不放宽每项每轮及合并 P95＜100ms 的阈值。完整表格与四组原始汇总见[本轮性能复验](windows-ui-performance.md#滚动条重构复验2026-09-27v161)。
- 独立复核 3,000 个时间戳差值、每轮 250 个唯一帧号、单轮／合并最近秩分位数与最大值；四组 72 个源码／入口／依赖哈希一致并与磁盘一致。各轮错误数、完整滚动范围、同步、输入、选择、撤销和隔离存储均通过。

### Spec 轴复审

首次发现 2 项验证漏洞：谱选择弹窗返回后的拖动缺少偏移断言，取消前没有真正移动进入拖动。现已补上实际偏移和移动后取消／同设备后续移动断言；复审两项关闭，剩余 Spec 问题 0。审查和上述原生性能实测独立验收，未用审查结果代替实测。
