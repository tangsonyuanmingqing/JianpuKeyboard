# V1 输入格式

## 标准文档

```text
[谱]
3 3 3 4 5 | 3 2 2 -
1 1 1 2 3 | 3 7 7 -

[词]
黑 黑 的 天 空 | 低 垂
亮 亮 的 繁 星 | 相 随
```

- `[谱]` 后是数字简谱
- `[词]` 后是歌词
- 允许多行
- 歌词与音符按全局顺序对齐，不按行重置
- 换行不重置歌词对齐

## 无标题输入

只输入简谱是合法的：

```text
3 4 5 6 7
```

也可以把简谱和歌词分开放到两个输入框。

## 音符

| 写法 | 音区 | 映射 |
| --- | --- | --- |
| `1 2 3 4 5 6 7` | 中音 | `A S D F G H J` |
| `1' 2' 3' 4' 5' 6' 7'` | 高音 | `Q W E R T Y U` |
| `1, 2, 3, 4, 5, 6, 7,` | 低音 | `Z X C V B N M` |

音区只看当前 token 自身的 `'` 或 `,`，不会沿用前一个音符的音区。

## 特殊符号

- `0`：休止。不映射，不消费歌词，必须保留。
- `-`：延音。不是新音符，不消费歌词，必须保留。
- `|`：小节线。必须保留。歌词中的 `|` 只作为结构标记，不是歌词音节。

## 歌词

优先使用空格分隔：

```text
黑 黑 的 天 空
```

连续中文字符默认必须按字符拆分。已经使用空格分隔的歌词也必须支持。该规则不改变空格分隔语义。

标点不会被当成音符。

## 对应规则

V1 使用全局顺序对齐：

1. 所有简谱行中的可消费 `Note` 按原始顺序组成一个连续音符序列。
2. 所有歌词行中的歌词 token 按原始顺序组成一个连续歌词序列。
3. 两者从头到尾依次对应。
4. 换行不重置对齐。

- 只有 `Note` 消费歌词
- `0`、`-`、`|` 不消费歌词
- 歌词为空或只有空白：视为未提供歌词，不校验数量，不产生 Warning
- 已提供歌词但数量不足：允许转换，未匹配 `Note.lyric` 为 `null`，必须 Warning
- 歌词过多：允许转换，必须 Warning，多余歌词不得静默丢弃，必须保留在转换结果中

跨行示例：

```text
谱：
3 4
5 6

词：
我爱你呀
```

对应：

```text
3 → 我
4 → 爱
5 → 你
6 → 呀
```

## 非法输入

以下内容必须报错，不能静默忽略：

- `1#`
- `2''`
- `abc`

错误必须包含行号、真实字符列号 `column`、token 顺序 `tokenIndex`、原始 token 和原因。

`column` 是源文本中的 1-based 字符列号。「第 8 个元素」对应 `tokenIndex`，不要把 `column` 写成元素序号。

用户可见错误格式：

```text
第 3 行第 8 个元素无法识别：1#
```
