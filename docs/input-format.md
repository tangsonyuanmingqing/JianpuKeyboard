# V1 输入格式

## 标准文档

```text
[谱]
3 3 3 4 5 | 3 2 2 -
1 1 1 2 3 | 3 7 7 -

[词]
黑 黑 的 天 空 | 低 垂 -
亮 亮 的 繁 星 | 相 随 -
```

- `[谱]` 后是数字简谱
- `[词]` 后是歌词
- 允许多行
- 歌词与音符按全局顺序对齐，不按行重置
- 换行不重置歌词对齐
- 歌词 `-` 是延续标记，不是新音节
- 谱面 `-` 是 Hold，不消费歌词

## 交替谱词与分句

`[谱]`、`[词]` 可以重复交替出现。每个 `[谱]` 与紧随其后的 `[词]` 就近配对；没有 `[词]` 的 `[谱]` 会按纯简谱转换。

```text
[谱] 3 4 5; 5 4 3 // 1 2
[词] 我爱你;你爱我 // 新歌
[谱] 6 7
[词] 好啊
```

- `//` 表示一句结束。谱句与词句按顺序配对。
- 英文 `;` 表示一行结束。谱行与词行按顺序配对。
- 在输入框按 Enter 会自动在当前行末补上 `;`；粘贴的旧换行仍按行结束处理。
- `//` 和 `;` 只控制输入结构，不会出现在转换结果、复制文本或 PNG 中。
- 英文 `;` 是格式符。若歌词需要普通分号，请使用中文全角 `；`。
- 歌词数量或分段数量不匹配仍会转换，并提示组、句、行位置；空句、空行、孤立 `[词]` 和连续 `[词]` 会阻止转换。

## 无标题输入

只输入简谱是合法的：

```text
3 4 5 6 7
```

也可以把简谱和歌词分开放到两个输入框。

## 音符

| 写法 | 音区 | 映射 |
| --- | --- | --- |
| `1 2 3 4 5 6 7` | 中音 | `A S D F G H J` |
| `1' 2' 3' 4' 5' 6' 7'` | 高音 | `Q W E R T Y U` |
| `1, 2, 3, 4, 5, 6, 7,` | 低音 | `Z X C V B N M` |

音区只看当前 token 自身的 `'` 或 `,`，不会沿用前一个音符的音区。

## 特殊符号

- `0`：谱面休止。不映射，不消费歌词，必须保留。
- 谱面 `-`：Hold。不是新音符，不消费歌词，必须保留。
- 歌词 `-`：continuation。若已有最近音节，则让下一个可消费 Note 沿用该音节；若还没有最近音节，则不消费 Note，不占槽位，产生 Warning。
- `|`：小节线。必须保留。歌词中的 `|` 只作为结构标记，不是歌词音节，也不占歌词槽位。

谱面 `-` 与歌词 `-` 同形不同义。

## 歌词

优先使用空格分隔：

```text
黑 黑 的 天 空
```

连续中文字符默认必须按字符拆分。已经使用空格分隔的歌词也必须支持。该规则不改变空格分隔语义。

连续中文末尾的 `-` 仍是 continuation，例如 `黑黑的天空低垂-` 拆成七个音节加一个 continuation。

标点不会被当成音符。拉丁词中的连字符（如 `well-known`）不是歌词延续。

## 对应规则

普通歌词音节默认对应一个 Note。歌词 `-` 仅在已有最近音节时消费下一个 Note 并沿用该音节；还没有最近音节时不消费 Note，后续普通歌词不能被跳过。

没有歌词 `-` 时，仍保持全局 1:1 对齐。不要根据相同汉字、行尾、小节或换行自动猜测一字多音。

V1 使用全局顺序对齐：

1. 所有简谱行中的可消费 `Note` 按原始顺序组成一个连续音符序列。
2. 所有歌词行中的音节与 continuation 按原始顺序组成一个连续序列。
3. 合法音节与合法 continuation 从头到尾对应到可消费 Note；无效前导 `-` 被跳过，不占用 Note。
4. 换行不重置对齐，也不清空最近一个音节。

- 只有 `Note` 消费普通音节和合法 continuation
- 谱面 `0`、谱面 `-`、谱面 `|` 不消费歌词
- 歌词 `|` 不占歌词槽位
- 没有 `previousSyllable` 的歌词 `-` 不占槽位，不进入 `unmatchedLyrics`，必须 Warning：`歌词延续标记 `-` 没有可延续的歌词，已忽略。`
- 完全没有音节也没有合法 continuation：视为未提供歌词，不校验数量不足/过多
- 已提供歌词时按 `lyricSlots = syllableCount + validContinuationCount` 与 `NoteCount` 比较
- `lyricSlots < NoteCount`：允许转换，未匹配 `Note.lyric` 为 `null`，必须 Warning
- `lyricSlots = NoteCount`：无数量 Warning
- `lyricSlots > NoteCount`：允许转换，必须 Warning，多余音节或合法 continuation 不得静默丢弃，必须保留在转换结果中

跨行 1:1 示例（没有歌词 `-`）：

```text
谱：
3 4
5 6

词：
我爱你呀
```

对应：

```text
3 → 我
4 → 爱
5 → 你
6 → 呀
```

没有 continuation 时，上一行多出来的 Note 仍会取到下一行音节：

```text
谱：
3 2 2
4 5

词：
低 垂
亮 空
```

对应：

```text
3 → 低
2 → 垂
2 → 亮
4 → 空
5 → null
```

歌词 continuation 示例：

```text
[谱]
3 3 3 4 5 | 3 2 2 -

[词]
黑 黑 的 天 空 | 低 垂 -
```

结果语义：

```text
3 → 黑
3 → 黑
3 → 的
4 → 天
5 → 空
3 → 低
2 → 垂
2 → 垂（歌词 continuation）
谱面 - → Hold，不消费歌词
```

下一行的「亮」必须从下一行第一个可消费 Note 开始。

无效前导 continuation 示例：

```text
谱：
3 4

词：
- 我
```

结果：

```text
3 → 我
4 → null
```

前导 `-` 不消费第一个 Note。必须 Warning：`歌词延续标记 `-` 没有可延续的歌词，已忽略。`

## 非法输入

以下内容必须报错，不能静默忽略：

- `1#`
- `2''`
- `abc`

错误必须包含行号、真实字符列号 `column`、token 顺序 `tokenIndex`、原始 token 和原因。界面会同时显示元素顺序与真实列号。

`column` 是源文本中的 1-based 字符列号。「第 8 个元素」对应 `tokenIndex`，不要把 `column` 写成元素序号。

用户可见错误格式：

```text
第 3 行第 8 个元素无法识别：1#
```
